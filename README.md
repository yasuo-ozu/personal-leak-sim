# 個人情報流出シミュレータ

企業からの個人情報流出と、断片的な公開情報・流出データから一人の人物が特定されていく過程を、**すべて架空のデータ**で疑似体験する教育用シミュレータです。情報漏えいとソーシャルエンジニアリングの怖さ、そしてその対策を学ぶことを目的にしています。

> ⚠️ **これは教材です。** 登場する人物・企業・住所・電話番号・メールアドレス・SNSはすべて架空であり、実在の個人を調べるための道具ではありません。各手口には、実際に報道・注意喚起されている事例と、身を守るための対策を併記しています。

コアのシミュレーションエンジンは Rust で実装し、WebAssembly にコンパイルして、CI で GitHub Pages に静的サイトとしてデプロイします。

## 体験できること

- **時間を進める** と、さまざまな業種の企業（ECサイト、通信教育、ファンクラブ、病院、自治体の委託先、SNS など）で個人情報の流出イベントが次々に発生します。各事件は、業種・顧客層（性別・年代）・流出規模（**日本人の何%か**）・流出した情報の種類・原因（不正アクセス、内部不正、設定ミス、誤送信など）を持ち、一部は後日「闇市場で流通」します。
- **自分の持っている情報** ウィンドウには、選んだペルソナに応じた持ち物（クラス連絡網、回覧板、年賀状、名刺、同窓会名簿、SNSのフォローなど）が並びます。ペルソナは高校生・会社員・子育て中の主婦・大学生・定年退職者から選べます。
- そこに登場する一人ひとりを **調査対象** として、断片的な情報から個人を特定する **ソーシャルエンジニアリングの手口** を実行できます。例えば「SNSを見る → 写真を発見 → 写り込みから最寄り駅 → ストリートビューで照合して住所 → 生年月日などの他の情報」のように、実際にある個人特定のケースを簡略化した手口を選んで連鎖させます。
- 手口は OSINT（公開情報の調査）、写真の解析・推理、流出データの悪用（名寄せ・リスト型攻撃）、対人のソーシャルエンジニアリング（なりすまし、プリテキスティング、フィッシング等）、物理的・制度的な手口（トラッシング、住民票の不正取得）など多数を用意しています。
- **各手口には時間コスト** があり、実行するとシミュレーション内の時計が進みます（その間にも事件は起き続けます）。最終的に得られた **取った情報リスト** には、情報ごとの「かかった時間」と、出どころを辿った「累計時間」が表示されます。
- 住所が判明した人物は **地図** 上に表示されます（判明の精度に応じて、確定点または推定範囲として）。
- **自分の流出** ウィンドウでは、あなた自身がどの事件に巻き込まれ、何が流出したかを確認できます。**答え合わせ** をオンにすると、掴んだ情報が本当に本人のものだったか（同姓同名や似た別人を掴んでいないか）を確認できます。

## 構成

```
core/     Rust 製シミュレーションエンジン（cdylib + rlib、wasm-bindgen）
web/      Vite + TypeScript + Leaflet のフロントエンド
.github/  GitHub Actions（テスト → wasm ビルド → Pages デプロイ）
```

乱数は `rand` + `rand_pcg`（PCG）を用い、シードから世界全体を決定的に生成します。人物・世帯・住所・学校・勤務先・SNS投稿はすべてコード内で合成しており、都道府県・市区町村名と代表座標のみ実在のものを地図表示に使用します。電話番号は割り当てのない番号帯、メールは `.example` ドメインで、実在の連絡先と一致しないようにしています。

## ローカルで動かす

必要なもの: Rust（stable）、`wasm32-unknown-unknown` ターゲット、[`wasm-pack`](https://rustwasm.github.io/wasm-pack/)、Node.js 20+。

```sh
# コアのテスト
cargo test

# wasm をビルドして web/src/pkg に出力
rustup target add wasm32-unknown-unknown
wasm-pack build core --target web --release --out-dir ../web/src/pkg --out-name leak_sim

# フロントエンド
cd web
npm install
npm run dev      # 開発サーバ
npm run build    # 本番ビルド（dist/）
```

## デプロイ

`main` ブランチへの push で `.github/workflows/deploy.yml` が走り、Rust のテスト → wasm ビルド → サイトのビルド → GitHub Pages へのデプロイを行います。リポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定してください。サブパス配信のため、ビルド時に `BASE_PATH=/<リポジトリ名>/` を渡しています。
